Amazon ASIN → 1688 Pro 商品溯源方案

在用户创建开发任务时，基于参考 ASIN 的图片、标题和公司统一采购价预算，自动召回、筛选、排序并补全 1688 商品与供应商数据，输出可解释的备选货源。

异步任务图搜 + 关键词价格阶梯兜底两阶段排序供应商匹配Pro 履约数据

3. 利润与价格门禁

参考 ASIN 的基础数据和公司内部接口计算出的“0% 毛利推算采购件价”，在选择 ASIN 创建开发任务时已经存在，应作为任务数据快照保存。该价格已包含运输等公司统一成本模型，定义为自动溯源的预算基准：

budgetPrice = internalZeroMarginPurchasePrice
计算结果系统判断允许动作禁止动作
budgetPrice < 0采购成本为 0 仍亏损重新调用公司接口计算一次；仍为负则跳过自动溯源，页面保留“手动溯源”不得自动放宽价格继续搜索
budgetPrice = 0免费采购才刚好盈亏平衡同样重算一次；仍为 0 则跳过自动溯源，允许用户手动不限价或自定义条件搜索不得自动进入正常候选流程
budgetPrice > 0 但极低理论可行、采购难度高进入严格预算搜索，允许无结果不得修改公司利润模型
budgetPrice 正常具备采购空间进入多路召回与价格阶梯兜底—
最终规则：重新计算后仍然 budgetPrice ≤ 0，状态写为 AUTO_SOURCING_SKIPPED_NON_POSITIVE_BUDGET，自动流程结束，模型本身不调整。用户仍可从任务详情发起手动溯源；默认不限制价格，或由用户填写自定义上限及其他条件。

4. ASIN 输入处理

无需再次抓取 ASIN：任务创建时已经带入商品图片、产品名称、Amazon 品类、基础属性和 0% 毛利推算采购价。溯源任务直接读取这份任务快照，仅对现有标题和属性做 AI 关键词结构化，并将现有图片上传换取 imageId。

原始输入

  • 任务内已有的 ASIN 与 Amazon 站点
  • 任务内已有的商品图片和产品名称
  • 任务内已有的 Amazon 品类和基础属性
  • 任务创建时已知的 budgetPrice

AI 结构化结果

{
  "coreCategory": "人体工学坐垫",
  "material": ["记忆棉"],
  "features": ["护腰", "久坐"],
  "color": "黑色",
  "excludeTerms": ["收纳袋", "坐垫套"],
  "queryCore": "人体工学坐垫",
  "queryAttribute": "记忆棉护腰坐垫"
}
关键词原则：不要把 Amazon 长标题原样传给 1688。品牌词、营销词、兼容机型堆叠和无关规格会降低召回；应拆成“核心品类词”和“属性组合词”。

5. 多路搜索召回

召回通道输入建议数量主要价值
图片搜索主图上传取得 imageId，可附简短 auxiliaryText首轮 20寻找外观、结构、构图相似商品
核心关键词queryCore首轮 20保证品类语义正确
属性关键词queryAttribute首轮 20补充材质、功能、用途等特征

价格阶梯只在候选不足时推进

层级priceEnd标识进入下一层条件
L0budgetPrice预算内去重且基本过滤后少于 15 条
L1budgetPrice × 1.10轻微超预算累计有效候选仍少于 15 条
L2budgetPrice × 1.20超预算累计有效候选仍少于 15 条
L3不传 priceEnd兜底作为最后一次召回；结果仍需强降权

每个 offer 记录首次命中的最低层级。达到 15～20 个有效候选即停止继续扩价，避免不必要的 API 调用。

5.1 自动溯源与手动溯源

模式触发价格规则其他条件
自动溯源任务创建且重算后 budgetPrice > 0按 L0～L3 阶梯自动兜底使用系统默认类目、国别偏好和排序配置
手动溯源用户在任务详情主动点击采购价 ≤ 0 时默认不限价；用户也可以自定义最低价/最高价允许修改关键词、类目、国别、评分阈值、销量等条件
重新溯源已有结果但用户需要更新使用最新采购价快照或本次手动条件生成新批次，保留历史结果和用户已选候选

5.2 过滤条件还是排序维度？

建议采用“少量硬筛选 + 多数软排序”。1688 字段可能缺失，评分设成默认硬门槛会把本来合适的商品直接丢掉。

条件系统默认建议原因手动模式
价格搜索硬筛选 + 详情复核自动模式有明确 budgetPrice；但详情仍要排除配件低价可不限价或自定义区间
Amazon/1688 类目高置信度时硬筛选能显著减少噪声；类目映射不确定时应改为排序加权允许用户指定或取消
目标国别/市场软排序优先API 的 country 是语言代码；实际市场能力依赖 regionOpp 或 Pro 区域标签，权限与覆盖可能不足用户明确选择“严格国别”时才使用有权限的区域筛选
商品/商家综合评分搜索级初排评分字段可能为空，且当前接口没有稳定的评分入参过滤；默认硬过滤容易导致无结果用户可设置最低分，作为搜索结果的后置硬过滤
物流、售后、履约率排序与风险标签适合区分优先级；缺失不能当作 0允许开启严格门槛，但应提示可能减少候选
销量/复购排序；必要时 saleFilterList默认软排序保留新品；用户明确要求成熟款时再用销量区间硬筛可配置近 7/14/30 天或累计销量区间
专利、白底图、一件代发业务需要时硬筛选语义相对明确，但必须确认 AppKey 权限作为开关型自定义条件
国别特别说明：Amazon 站点可自动带出“目标市场偏好”，用于排序加分；不要把接口的 country=en 当成美国市场筛选。只有已确认 Pro 权限和合法枚举/标签时，才把区域条件下推为搜索过滤。

6. 合并、去重与基础过滤

  1. 按 offerId 去重。同一个商品可保留多个命中来源及各自排名。
  2. 记录来源。例如 image、keyword_core、keyword_attribute 和首次价格层级。
  3. 做基础硬过滤。明显错误类目、无图片、无价格、已知不可售商品直接排除。
  4. 不要解析 traceInfo 作为稳定相似度。它是追踪与内部检索信息，结构和口径可能变化。
  5. 双通道命中加分。同时被图搜和关键词命中的商品置信度高于单一通道。
{
  "offerId": "1084127309764",
  "sources": ["image", "keyword_core"],
  "sourceRanks": { "image": 3, "keyword_core": 8 },
  "firstFallbackLevel": "L0",
  "searchMinPrice": 2.84,
  "budgetPrice": 30.00
}

7. 两阶段排序

7.1 搜索级初排：从去重候选缩小到 15～20 条

维度建议权重数据来源与计算
多路召回排名30%图搜、核心词、属性词排名融合；图搜可给予略高权重
标题语义相似度25%ASIN 结构化标题与 subject/subjectTrans 的语义相似度
类目一致性15%目标品类与 thirdCategoryId、标题品类的一致性
双通道/多通道命中10%图片与关键词同时命中加分
搜索价格10%只作宽松初筛；搜索最低价可能是配件价
商家摘要10%服务分、物流分、售后分、复购等搜索摘要

多路排名可以采用 Reciprocal Rank Fusion：

retrievalScore = Σ sourceWeight / (60 + rank)

sourceWeight:
  image             = 1.2
  keyword_core      = 1.0
  keyword_attribute = 0.8

7.2 详情级复排：从 15～20 条中输出最终 10 条

维度建议权重重点判断分值条
商品相似度35%视觉、标题、属性、类目与 ASIN 主体的一致性
主体 SKU 价格20%排除配件 SKU 后，与 budgetPrice 比较
供应商质量15%服务、商品、物流、售后、纠纷、经营身份
履约能力10%发货承诺、揽收、履约、退货率及 Pro 字段
内部供应商匹配10%供应商名称精确匹配；省市与“渠道-1688”类型辅助确认
销量与复购5%销量区间、复购率；缺失时不按 0 处理
数据完整与风险5%SKU、证书、包装、发票、字段可信度及异常处罚
供应商多样化：最终 Top 10 中同一 1688 供应商（优先按 companyName，缺失时按 sellerOpenId）默认最多保留 2 个商品，避免结果被单一供应商占满。

8. 价格等级与最终判断

搜索价格只用于召回；最终必须在商品详情中找到与 ASIN 主体可比的 SKU，并使用该 SKU 价格判断预算。

价格等级可比 SKU 价格 / budgetPrice价格分处理
A · 预算内≤ 100%100优先候选
B · 轻微超预算> 100% 且 ≤ 110%80L1 兜底，可展示超出比例
C · 超预算> 110% 且 ≤ 120%60L2 兜底，明显降权
D · 高度超预算> 120%20～40仅在预算内候选不足时展示
N · 无法判断无法识别主体 SKU0～30标记“价格待人工确认”，不得用最低配件价替代

配件低价识别

结合 ASIN 主体、SKU 属性、SKU 图片和排除词识别“收纳袋、替换套、赠品、补差价”等配件。示例：

budgetPrice       = ¥30.00
searchMinPrice    = ¥2.84   // 绒布收纳袋，不可作为主体价格
comparableSkuPrice= ¥35.00  // 坐垫主体
priceRatio        = 116.67%
priceGrade        = C
overBudgetRate    = 16.67%

9. 商品详情补全与校验

初排后建议查询 15～20 条详情，而不是只查询恰好 10 条；详情校验会淘汰低价配件、下架商品、错误类目和数据严重异常的候选。

模块字段示例用途校验重点
商品offerId、status、subject、categoryId确认商品状态和品类必须 published；类目不能明显错误
媒体productImage、detailVideo、description内部展示和 AI 理解description 为 HTML，必须安全清洗
属性productAttribute、*Trans与 ASIN 属性比对同一属性可能出现多个值
SKUskuId、skuAttributes、price、amountOnSale识别主体 SKU、价格和库存排除配件，避免最低价误判
物流weight、length、width、height、sendGoodsAddressText物流风险展示0 尺寸、异常轻重量、商家自填需标记
供应商sellerOpenId、companyName、sellerDataInfo匹配内部供应商并评价发货地不等于公司注册地址
发票与证书invoiceInfo、certificateList采购合规辅助缺失不等于否；最终需供应商确认
字段差异：搜索返回 promotionURL，详情返回 promotionUrl；搜索链接通常带更完整的归因参数，应保留搜索值。搜索与详情的商家评分也可能来自不同快照。

10. 内部供应商匹配

按现有内部数据特点，供应商名称是主匹配键，采用精确匹配；省市和供应商类型只做辅助核验，不使用发货地。

步骤规则结果说明
11688 companyName 与内部供应商名称精确一致内部供应商已匹配内部供应商名称通常不重复，因此直接标记匹配
2核对 companyAddress 的省市与内部供应商省市一致则增加辅助确认标记省市不一致时不自动取消名称匹配，但显示“地址不一致”提醒
3核对内部供应商类型是否为“渠道-1688”一致则增加渠道确认标记类型只作辅助，不作为名称精确匹配的必要条件
4供应商名称没有精确命中临时新供应商只随候选商品展示，不创建供应商档案、不自动绑定
 
{
  "companyName": "苍南县新敏百货商行",
  "internalSupplierId": "SUP-00125",
  "matchType": "exact_company_name",
  "matched": true,
  "provinceCityMatched": true,
  "supplierType": "渠道-1688",
  "supplierTypeMatched": true,
  "matchReason": "供应商名称精确一致，省市和渠道类型辅助一致"
}
地址口径：只使用 companyAddress 提取的省市辅助比对；明确忽略 sendGoodsAddressText，因为它只是发货地。对于名称精确命中但省市或类型冲突的情况，仍标记为已匹配，同时显示辅助信息冲突，供用户核对。

11. 内部页面展示建议

最终建议：把“1688 备选货源”直接铺在参考产品区和备选供应商区之间，作为任务详情的独立模块。候选货源需要比较、排序、多选并持续回看，不适合只放在一次性弹窗中；自定义溯源条件和单条商品的完整 SKU/评分解释适合弹窗或右侧抽屉。

11.1 结合现有任务详情页的推荐位置

  └─ 从候选货源选择后预填或创建
承载方式适合内容优点结论

11.2 入口与联动定稿

位置入口/控件点击后的行为是否推荐
参考产品模块右上角“查看全部候选”仅滚动到下面的 1688 备选货源模块，并切换为“全部 ASIN”可选；不是唯一入口
每个参考 ASIN 的操作列候选货源（10）滚动到下面的独立模块，并自动筛选为当前 ASIN推荐保留
参考 ASIN 采购价 ≤ 0手动溯源打开自定义条件弹窗；默认不限价必须保留
1688 备选货源模块ASIN 筛选、全部 ASIN、重新溯源、自定义溯源直接更新当前候选表格主操作区
候选商品行查看详情打开右侧抽屉或大弹窗，查看 SKU、评分拆分和风险推荐
不要把“查看候选”设计成打开另一张候选列表弹窗。它只负责定位到独立模块并带入当前 ASIN 筛选。这样用户关闭详情或切换 ASIN 后，候选结果仍保留在任务页面中。

11.3 参考产品行上的操作

采购价状态自动动作页面操作提示
budgetPrice > 0创建任务后自动溯源查看候选、重新溯源、自定义溯源显示进度、完成时间和候选数量
budgetPrice ≤ 0自动重算一次；仍 ≤ 0 则跳过重新计算、手动溯源“自动溯源已跳过；手动溯源默认不限价”
自动接口失败保留已有部分结果重试、手动溯源显示失败通道与 request_id

11.5 1688 备选货源表格建议列

商品匹配双通道命中相似度 89

展示图片、标题、类目、匹配原因以及主体 SKU。

价格判断预算内价格等级 A

同时显示预算价、主体 SKU 价、差额和价格可靠性。

供应商内部已合作精确匹配

显示公司名、sellerOpenId、地区、评分和匹配原因。

候选列表最低展示字段

  • 参考 ASIN（任务包含多个 ASIN 时用于分组或筛选）
  • 商品图、中文/英文标题、1688 商品链接
  • 商品综合分及各维度拆分，不能只显示一个黑盒分数
  • 预算价、搜索最低价、主体 SKU 价、价格等级和超预算比例
  • 起订量、一件代发、混批、库存和关键 Pro 履约字段
  • 供应商名称、公司省市、内部名称精确匹配结果、内部供应商类型
  • 风险标签：配件低价、包装异常、字段缺失、证书/发票待确认

主表不要把全部详情字段横向铺开。推荐冻结“勾选、参考 ASIN、商品图片/标题”三列，右侧固定“选择为货源/查看详情”；评分拆分、全部 SKU、详情图和发票证书放入抽屉。

预算范围内没有结果时，不显示“没有相似商品”，而显示：“预算内未找到有效货源，已放宽价格范围并提供 N 个兜底候选。”

14. 第一阶段验收标准

  1. 利润门禁正确。采购价重算后仍 ≤ 0 的任务不自动调用 1688，并给出明确原因和手动溯源入口。
  2. 召回可追溯。每个候选都能看到来源、排名、价格层级和使用的查询词。
  3. 排序可解释。展示相似度、价格、供应商、履约和风险等维度得分。
  4. 价格不被配件误导。最终预算判断使用主体可比 SKU，而不是搜索最低价。
  5. 供应商匹配符合内部规则。名称精确一致即标记已匹配，省市和“渠道-1688”辅助展示；未命中仅作为临时新供应商。
  6. 结果有供应商多样性。默认同一 1688 供应商不超过 2 个最终候选。
  7. 详情字段安全。HTML 描述经过清洗，空值、异常重量和 0 尺寸均有明确状态。
  8. 部分失败可用。图搜或关键词单路失败时仍可返回另一通道的候选。
  9. 最终输出稳定。尽量输出 10 个；不足时展示实际数量和不足原因，不用低质量商品强行补满。
