# AC开发任务与预立项整合方案

## 查看入口

- `plan.html`：整合方案，包含四阶段规划、第一阶段实施方案及三个原报告字段处理附表。
- `市场分析报告交互原型.html`：可离线打开的交互原型，样式、脚本和示例图片均已内嵌。

将两份 HTML 保留在同一目录，双击任一页面即可查看，通过左下角「整合方案 / 交互原型」导航互相跳转。方案页另有章节目录，支持浏览器打印。在线访问时导航使用分离版 `index.html`，支持浏览器分别缓存样式、脚本及图片；离线访问保留单文件入口。图片按需加载并异步解码。

方案以当前原型口径为准：采购备注使用单行文本合并维护且必填；采购链接为选填的单行文本；海运-多渠道利润测算（OP）改为保存后按SKU模拟发起无产品模板测算，固定7个平台9个店铺；配件搭配清单使用固定一行高度、可纵向滚动的多行文本框，按 SKU 维护并关联包装清单。第一阶段保留开发任务与预立项各自的审核流程。

## 编辑与构建

- `index.html`：原型页面及继承的 AC、1688 溯源基础交互。
- `market.css` / `market.js`：市场分析、报告预览、待开发产品补充字段等样式与交互。
- `layout.css` / `layout.js`：模块布局、导航及收起展开。
- `report-data.js` / `assets/`：原报告字段、示例内容及图片。
- `plan.html`：独立维护的方案页，无外部依赖。
- `build_standalone.py`：使用 Python 标准库，从上述原型源文件重新生成 `市场分析报告交互原型.html`。

在本目录执行 `python build_standalone.py` 即可重新构建原型。修改方案页无需构建。

## 演示边界

本项目仅为前端原型，不对接后台、真实审批或生产利润计算器。OP使用本地异步服务模拟请求、方案编号、成功、缺参及失败重试状态；当前原型显示的利润率为演示样例，不是真实接口结果。SKU装箱及单套包装信息按适用场景必填，并映射至SPU草稿；售卖季节固定传旺季。利润率列与操作列固定在列表右侧，明细按平台、店铺、测算时间、利润率展示，负值标红。利润率以百分数数值维护（12.5表示12.5%），全部大于0且至少一个大于10%才通过，仅在SKU行判断及展示，SPU行留空。状态包括待测算、测算中、利润通过、利润未通过、测算失败；通过／未通过为明细链接，失败可按当前SKU数据重新测算，其他状态没有重复触发入口。初始提供失败、通过、未通过三个SKU演示。预计售价（USD）使用单个数字，旧区间迁移取原最低价。装箱仅支持一箱多件及一件一箱，不支持多箱；装箱及包装信息只在编辑弹窗维护，列表单位只标于字段名。任务、历史报告、权限及 ASIN 数据为演示数据；当前任务的修改使用浏览器本地存储。预立项在开发任务审核通过后引用审核通过时的报告；报告审核通过后不再修改。

验证包括本地链接、脚本初始化及关键交互的模拟 DOM 检查；实际浏览器视觉与业务验收需在可打开本地 HTML 的浏览器中进行。


## AI辅助演示版

- 在线入口：`ai-index.html`；离线入口：`市场分析报告AI辅助原型.html`。原版、AI辅助版、整合方案可通过左下角导航切换。
- AI版由原版复制生成，保留原有功能；使用独立浏览器存储 `ac-market-analysis-ai-v1`，首次打开可复制当前原版草稿，后续互不覆盖。
- 类目标题行“AI获取分析”按当前站点、品类等级、调研品类执行一次批量任务；榜单及8项分析均支持标题行“AI重新获取”。回填演示数据依据、结论和适用图表。
- 首次整体获取特意模拟“上架时间分布”获取失败，可用该模块“AI重新获取”完成恢复。其余模块独立返回，重复点击不会并发启动相同任务。
- 竞品右侧顶部操作行显示当前ASIN和“AI获取竞品分析”；切换ASIN后已发起任务仍只更新原ASIN。
- 人工修改的结论、图表、数据依据和竞品字段不会自动覆盖；获取期间继续编辑也会保留。口径、权限或任务状态变化后，不回填旧任务结果。
- 此版使用本地模拟数据，不调用真实模型或外部数据接口。`ai-assist.js`为AI扩展源码；运行 `build_standalone.py` 同时生成两版在线入口、独立控制器和离线文件。
