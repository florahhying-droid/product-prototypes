# AC开发任务与预立项整合方案

## 查看入口

- `plan.html`：整合方案，包含四阶段规划、第一阶段实施方案及三个原报告字段处理附表。
- `市场分析报告交互原型.html`：可离线打开的交互原型，样式、脚本和示例图片均已内嵌。

将两份 HTML 保留在同一目录，双击任一页面即可查看，通过左下角「整合方案 / 交互原型」导航互相跳转。方案页另有章节目录，支持浏览器打印。在线访问时导航使用分离版 `index.html`，支持浏览器分别缓存样式、脚本及图片；离线访问保留单文件入口。图片按需加载并异步解码。

方案以当前原型口径为准：采购备注使用单行文本合并维护且必填；采购链接为选填的单行文本；海运-多渠道利润测算（OP）改为保存后按SKU模拟发起无产品模板测算，固定7个平台9个店铺；配件搭配清单使用固定一行高度、可纵向滚动的多行文本框，按 SKU 维护并关联包装清单。第一阶段保留开发任务与预立项各自的审核流程。

## 编辑与构建

- `index.html`：原型页面及继承的 AC、1688 溯源基础交互。
- `market.css` / `market.js`：市场分析、报告预览、待开发产品补充字段等样式与交互。
- `layout.css` / `layout.js`：模块布局、导航及收起展开。
- `report-data.js` / `assets/`：原报告字段、示例内容及图片。
- `plan.html`：独立维护的方案页，无外部依赖。
- `build_standalone.py`：使用 Python 标准库，从上述原型源文件重新生成 `市场分析报告交互原型.html`。

在本目录执行 `python build_standalone.py` 即可重新构建原型。修改方案页无需构建。

## 演示边界

本项目仅为前端原型，不对接后台、真实审批或生产利润计算器。OP使用本地异步服务模拟请求、方案编号、成功、缺参及失败重试状态；当前原型显示的利润率为演示样例，不是真实接口结果。SKU装箱及单套包装信息按适用场景必填，并映射至SPU草稿；售卖季节固定传旺季。利润率列与操作列固定在列表右侧，明细按平台、店铺、测算时间、利润率展示，负值标红。利润率以百分数数值维护（12.5表示12.5%），全部大于0且至少一个大于10%才通过，仅在SKU行判断及展示，SPU行留空。状态包括待测算、测算中、利润通过、利润未通过、测算失败；通过／未通过为明细链接，失败可按当前SKU数据重新测算，其他状态没有重复触发入口。初始提供失败、通过、未通过三个SKU演示。预计售价（USD）使用单个数字，旧区间迁移取原最低价。装箱仅支持一箱多件及一件一箱，不支持多箱；装箱及包装信息只在编辑弹窗维护，列表单位只标于字段名。任务、历史报告、权限及 ASIN 数据为演示数据；当前任务的修改使用浏览器本地存储。预立项在开发任务审核通过后引用审核通过时的报告；报告审核通过后不再修改。

验证包括本地链接、脚本初始化及关键交互的模拟 DOM 检查；实际浏览器视觉与业务验收需在可打开本地 HTML 的浏览器中进行。


## AI辅助演示版

- 在线入口：`ai-index.html`；离线入口：`市场分析报告AI辅助原型.html`。原版、AI辅助版、整合方案可通过左下角导航切换。
- AI版由原版复制生成，保留原有功能；使用独立浏览器存储 `ac-market-analysis-ai-v1`，首次打开可复制当前原版草稿，后续互不覆盖。
- 类目标题行“AI获取分析”按当前站点、品类等级、调研品类执行一次批量任务，只生成8项类目分析，不包含榜单和竞品分析；榜单继续支持单项重新获取。
- 前6项采用上下结构：上方只读数据表格（主页面4—6行关键数据，来源／样本／时间置于表格下），下方136px分析结论文本框。完整数据在右侧抽屉查看，包括24个月销量序列，不补全记录中缺失的月份或推算销售额。
- 数据仅转录自 `D:/Codex工作区/AI调用记录.md`，整理于 `ai-category-data.js`。Sorftime Top 100与SellersSprite 63商品样本分开展示；来源未注明的统计月明确标注，消费者画像为用途推断。
- 上传截图后替换表格展示，支持放大、更换、删除与恢复AI数据；结构化数据和人工结论保留。有AI数据时满足分析依据必填，无需再上传截图。报告预览按当前选择展示表格或截图及已保存结论。
- 类目重新获取遇到人工内容时，先提供保留／覆盖／取消选择；任务期间的新编辑始终保留。消费者画像、使用场景保持纯文本结论。
- 竞品右侧顶部操作行显示当前ASIN和“AI获取竞品分析”；切换ASIN后已发起任务仍只更新原ASIN。
- 人工修改的结论、图表、数据依据和竞品字段不会自动覆盖；获取期间继续编辑也会保留。口径、权限或任务状态变化后，不回填旧任务结果。
- 此版使用本地模拟数据，不调用真实模型或外部数据接口。`ai-assist.js`为AI共享扩展源码，`ai-category-view.js`负责类目结构化依据交互，`ai-ranking-view.js`负责榜单表格、截图及完整榜单抽屉；运行 `build_standalone.py` 同时生成两版在线入口、独立控制器和离线文件。

竞品市场定位在两版中均按类目分析的市场趋势／流量周期、使用场景、消费者画像同步至节日周期／流量时段、核心消费场景、目标客群。未人工修改的字段随类目保存及AI返回更新；人工修改（含清空）后保持独立。定位标题行支持“同步类目分析”，覆盖人工内容前确认。AI版界面已去除环境说明文字，既有草稿中的环境标记会同步清理；数值、样本与估算说明保留。

AI版榜单默认使用AI结构化数据：新品TOP10与小类近30天TOP各含原调用记录的10条商品，新品默认展开，小类近30天TOP默认折叠，展开后主页面显示3条，“查看全部10条”打开右侧抽屉展示完整数据及来源口径。新品按2026-08-02至2026-11-02上架筛选，小类榜按预估月销量排序（非可核验的近30天实际销量）；缺失价格、评分不补值。两个榜单支持独立AI获取、上传截图／重新上传、放大、删除及恢复AI数据；报告按当前表格或截图展示，AI数据满足新品榜单必填。标准版继续原有图片模式。

AI版顶部不再显示整体填写数量。不展示类目全局“全部收起／全部展开”，各模块仍可独立展开收起。唯一的类目全局AI主按钮紧接调研品类行的“复用历史分析”之后：有效站点、等级及已确认品类齐备后可用，首次“AI生成分析”，生成结果后“AI重新生成”；有人工修改时确认覆盖。榜单来源压缩为一行，详细口径保留在完整榜单抽屉；表格态“替换为截图”，截图态“更换截图／恢复AI表格”。保存状态与单项AI操作留在模块标题中，不设置底部浮动操作栏，保留版本切换导航和报告预览。

AI辅助版细节：榜单入口统一为“查看完整数据”，新品TOP10以星号标记必填；移除竞品全局折叠操作和四个编辑模块的填写进度。分析模块不显示成功保存状态，调研品类保存标记保留，保存失败仍可提示重试。待开发产品列表隐藏起订量、配件搭配清单，编辑及查看弹窗保留；SPU和SKU均提供只读“查看”，任务查看人同样可用，禁用修改和保存。维护有效采购链接后，来源下显示“查看货源”。
