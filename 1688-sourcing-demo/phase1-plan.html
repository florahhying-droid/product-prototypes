目标与一期范围

在开发任务中并行执行1688货源溯源与内部供应商溯源，分别承接外部候选商品和内部供应商结果。两条链路独立执行、独立记录状态，共用任务参考ASIN、备选供应商和现有提交审核流程。

链路输入与处理结果与落点
1688溯源ASIN图片与AI提取关键词 → 搜索召回 → AC去重过滤 → 内部供应商匹配与资质处理 → 综合评分每个ASIN最终最多10个候选商品；人工选择offer与SKU后生成待开发SPU/SKU，并处理备选供应商
内部供应商溯源复用现有英文标题相似、图片相似SKU能力 → 合并SKU → 查询关联供应商 → 用户权限过滤命中的内部供应商自动加入任务备选供应商，不依赖用户先选择1688商品
共同触发：新建任务成功后处理全部初始参考ASIN；待分配、调研中的任务新增ASIN成功后仅处理新增部分。自动执行不额外要求用户确认，也不扩大新增ASIN、删除ASIN等既有权限。

AI仅为1688搜索提取中文关键词；1688相关性复用接口原始排序，内部相似能力复用现有接口。

供应商信息处理

  • 使用1688公司名称与内部供应商名称精确匹配；地址省市和“渠道-1688”类型仅作辅助校验。匹配成功保存内部供应商ID，并读取实际内部状态和结算方式。
  • 搜索结果不保证返回公司名称；需要参与内部匹配和评分时，用offerId补查商详或复用已获取资料。补查失败记录资料缺失；内部供应商采用名称精确匹配。
  • 从商家身份、诚信通年限等数据提取资质；只展示实际命中的诚信通X年、超级工厂、实力商家，缺失展示“--”，不补造年限或身份。
  • 内部供应商匹配结果用于候选展示与评分；确认生成待开发产品时关联任务备选供应商。内部供应商自动加入属于第二部分独立链路。
评分前获取合格候选所需的供应商资料，优先复用搜索返回字段与缓存；缺少匹配信息时按需补查商详。确定最终候选后补齐SKU等展示详情，调用采用缓存、并发控制和超时处理。

1.4 综合评分与推荐结果

总分100分，由搜索相关性40分和供应商综合评分60分组成。

搜索相关性：40分

  • 使用1688返回的默认相关性排名，图搜权重1.0，关键词权重0.7；排名从1开始。
  • RRF融合公式：R = 1 / (60 + 图搜排名) + 0.7 / (60 + 关键词排名)。仅命中一个通道时，未命中通道贡献为0。
  • 同一ASIN、同一溯源批次，将全部页合并、去重并通过过滤的候选作为统一评分集合，取其中最大的R值为Rmax。搜索相关性分 = 40 × R / Rmax，最高为40分；在最终选取10个商品之前计算，不逐页归一化，不跨ASIN或跨批次共用Rmax。集合为空时直接输出0条；Rmax为0时相关性分记为0。

供应商综合评分：60分

组成情况分值
我司内部供应商（最高35分）匹配有效内部供应商，且有账期35
我司内部供应商匹配有效内部供应商，无账期18
我司内部供应商未匹配内部供应商，或内部状态非有效0
商家资质（最高25分，可叠加）超级工厂15
商家资质实力商家10
商家资质同时具有超级工厂、实力商家25（15＋10）
商家资质仅诚信通会员0；诚信通作为AC准入条件

内部供应商35分、18分档位互斥。内部状态必须读取实际系统状态；草稿、锁定、停用等不能套用“有效供应商”加分。显示了结算方式不等于有账期：“预付款100%”不能算月结账期；阿里月结X天等按内部结算方式字典中的付款类型判断。无法归类时补取核验后评分，记录资料异常。

最终结果

按综合得分从高到低输出，每个ASIN最多10个商品。合格结果不足10条时按实际数量展示，不放宽条件。同一ASIN全部页的候选统一按综合得分排序；总分并列时，依次按搜索相关性分降序、图搜原始排名升序、关键词原始排名升序排序；未命中通道的排名排在已命中之后。

有账期判断使用内部结算方式字典；状态非有效或缺失时内部供应商项记0分；未返回的商家身份不计对应资质分。

1.6 创建待开发产品与信息维护

确认待开发变体

点击“生成待开发产品（N）”打开“确认待开发变体”弹窗，按offer分组显示SKU并默认全选。可取消不开发的变体；某offer选择0个SKU时不生成其SPU；全部SKU未选择时禁用确认。弹窗统计随内容滚动吸顶，确认前展示将生成的SPU与SKU数量。

选中数据业务结果取值与去重
一个offer一个待开发SPU标题、主图、供应商、来源链接取对应offer
一个被选中的1688 SKU该SPU下一个待开发SKU规格、SKU图、采购价、库存取该SKU；参考产品关系默认“相同款”，支持编辑为“相似款”；包装尺寸重量按实际数据维护
匹配的内部供应商关联已有正式供应商任务内按内部供应商ID去重；若已由内部溯源或人工加入则复用，列表首次来源不覆盖
未匹配的1688供应商按现有机制处理临时供应商按供应商公司名称精确去重；来源为1688备选货源

正式关系与防重复

保存任务—参考ASIN—1688 offer—待开发SPU关系，同时保留来源链接、溯源批次、供应商、操作人与时间。同一任务＋ASIN＋offerId禁止重复生成；重新溯源召回同一offer时识别既有关系并保持已转产品标记。生成应统一处理产品、供应商与来源关系，失败时避免只写入部分业务数据。

产品维护

  • 列表和编辑弹窗共用一份SPU/SKU数据；编辑、删除同步，不维护另一套独立展示数据。
  • 来源展示“1688备选货源 · 查看原商品 ↗”，使用搜索promotionURL，兼容商详promotionUrl。手动创建仍显示“手动添加”；历史已有任务供应商来源默认“手动添加”。任务供应商仅记录首次成功加入的来源，解绑后再次加入按本次方式记录。
  • 编辑沿用产品标题、供应商、系统品类、图片、参考产品及相同款/相似款、采购价、预计售价、起订量、包装尺寸重量、友商销售材料等现有字段。
  • 1688规格显示在SKU产品标题下。预生成产品缺少系统品类、预计售价时默认显示红色内联提示；SKU行未维护售价时显示橙色“待维护”标签；编辑表单及提交校验使用红色提示。
  • 长标题最多两行省略，悬浮看全文；SKU和SPU删除均需二次确认。

提交审核校验

  • 没有任何待开发SKU时阻止提交，以红色提示至少需要一个待开发SKU，并定位、展开待开发产品模块。
  • 存在SPU没有可提交SKU时阻止提交，以红色提示补充SKU；删除最后一个SKU本身不自动删除SPU。
  • 产品必填项未完成、仍有信息待维护或原有校验不通过时，阻止提交，以红色提示“当前仍有待开发产品信息未维护，请处理完成后再提交”，定位待开发产品模块。
  • 供应商绑定、参考产品处理等原有提交规则继续执行，不因自动补入供应商而绕过。进入审核中后按现有权限只读。

待分配 / 调研中新增ASIN成功仅对新增ASIN增量执行已有ASIN不重查；内部供应商按钮同步展示进行中状态

  • 任务无参考ASIN时不发起空请求，提示先添加参考ASIN。

2.2 内部匹配执行流程

步骤处理内容约束与输出
1. 更新及获取相似SKU更新ASIN英文标题相似SKU；调用重复开品图片相似接口获取图片相似SKU复用现有能力、现有入参出参及错误处理，不自行编造接口名称或新匹配模型
2. 合并相似SKU合并标题相似和图片相似结果，按SKU去重保留标题、图片或双来源关联，扩展候选范围
3. 获取关联供应商查询相似SKU关联的内部供应商一个SKU可关联多家供应商，多SKU可指向同一家供应商
4. 供应商权限过滤与当前用户有权限的供应商取交集仅保留权限范围内供应商；自动执行的身份上下文沿用现有权限机制，不以系统执行绕过用户权限
5. 生成内部溯源结果按内部供应商编号 / ID去重返回已有的名称、编号、实际状态、类型和结算方式，保留相似SKU与匹配来源用于追溯

本链路按现有相似匹配与供应商权限规则获取内部供应商。结果范围以现有接口和权限机制为准，状态按实际值展示，包括有效、草稿、锁定等。

2.3 自动加入、去重与来源规则

规则处理方式
自动加入内部溯源命中的权限内供应商自动加入当前任务备选供应商，不要求开发人再次选择
任务内去重按内部供应商ID唯一识别；同一供应商被多个ASIN、多个相似SKU或两种相似方式命中，任务内仍只保留一条
跨链路复用与手动绑定、1688生成产品共用去重规则；已在任务中的供应商不重复添加
首次来源列表只记录首次成功加入当前任务备选供应商列表的来源；重复命中不覆盖
来源枚举手动添加 / 内部供应商溯源 / 1688备选货源
重新溯源只补充新命中供应商，不自动删除本次未命中的已有供应商，也不覆盖产品、人工维护或首次来源
解绑后再次加入删除 / 解绑后再次加入时按本次加入方式重新记录来源；重新命中且满足权限时可再次加入，不设置永久排除名单
删除参考ASIN删除该ASIN当前匹配状态和关联结果；已加入备选供应商以及已关联产品不自动删除，已有来源追溯记录保留
来源示例：先由内部供应商溯源加入，之后通过1688商品生成产品，来源仍为“内部供应商溯源”；先手动加入，之后重复命中，仍为“手动添加”。解绑后再次由1688生成产品加入，来源记录为本次的“1688备选货源”。

系统需保留供应商与相似SKU、参考ASIN、匹配来源（标题 / 图片）及批次时间的关联，供后续追溯推荐依据。后台命中记录与前端首次加入来源分别保存；多个来源命中不在列表重复堆叠。

字段 / 操作展示规则
