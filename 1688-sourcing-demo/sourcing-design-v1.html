1688 溯源一期产品方案

一期直接使用寻源通已有的商品相关性、筛选及排序能力，AC 不额外建设商品相似度和推荐模型。

4个1688接口图搜主序列最多10条 / ASIN名称精确匹配货源关系可追溯
一期方案目录方案定位业务闭环1. 数据获取与处理2. 业务页面与结果承接验收标准

1688溯源不是孤立搜索页面，最终结果必须承接到现有开发任务的备选供应商、待开发产品和提交审核流程。

1. 数据获取与处理

1.1 触发与4个接口

product.image.upload上传ASIN主图，取得imageId。
product.search.imageQuery图片搜索，作为主要结果序列。
product.search.keywordQuery关键词搜索，作为补充召回。
product.search.queryProductDetail仅为最终候选补齐标题、SKU、价格库存、属性、供应商、表现、履约品质与发票。

Amazon品类 + 产品中文标题由AI清洗为1条简洁中文搜索词；失败时回退中文产品标题。

1.2 自动溯源触发与采购价格

自动溯源不只绑定创建任务：只要参考ASIN成功新增到处于“调研中”的开发任务，就初始化该ASIN状态并独立执行价格判断。任务创建时已有ASIN与任务创建后新增ASIN使用同一规则。

场景采购价上限处理
有目标采购价区间取区间上限自动溯源
无目标采购价，0%毛利推算采购价 > 0使用0%毛利推算采购价自动溯源
目标采购价为0，且0%毛利推算采购价为空或 ≤ 0不可用不调用1688，记为“未自动溯源”，允许任务开发人手动不限价溯源

1.3 一期准入与采购可行性规则

分组页面业务条件研发字段映射来源
货源准入跨境精选货源isSelect = true沿用原人工抓取规则
有跨境推广链接搜索优先取 promotionURL；详情兼容 promotionUrl
商品体验分 > 4.0sellerDataInfo.offerExperienceScore > 4.0
采购可行性采购价 ≤ 当前参考产品价格上限搜索价格上限映射AC结合当前开发任务新增
起批量 ≤ 当前参考产品目标采购量搜索最小起批量映射
综合服务分和近30天品质退货率不作为一期硬筛选条件；相关字段仍可在商品详情中作为辅助判断信息展示。

1.4 新增ASIN增量处理

  1. 新增成功后，仅为本次新增ASIN初始化溯源状态、计算价格条件并调用1688。
  2. 一次新增多个ASIN时，各ASIN独立维护状态、候选数量、sourcingAt和候选结果。
  3. 不得因新增ASIN重新溯源任务中已有ASIN；“全部ASIN”数量和结果只做增量汇总。
  4. 自动溯源是新增成功后的系统动作，不要求用户再次确认或进行按钮级授权。

1.5 召回、合并与商详

  1. 图搜pageSize优先50；词搜联调确认支持50时使用50，否则按接口实际最大值；每个通道最多2页。
  2. 图片结果为主序，关键词结果补充；按offerId去重，记录图搜、关键词或图搜+关键词。
  3. 不足10条时才请求下一页；达到10条、无更多结果或达到2页即停止，不放宽条件。
  4. 同一sellerOpenId最多保留2个商品；每个ASIN最多10条。
  5. 搜索阶段宽召回，商详阶段窄补充；仅对最终展示候选查询详情。

1.6 供应商匹配与时间

以1688 companyName与内部供应商名称精确匹配。匹配成功保存internalSupplierId和sellerOpenId；未匹配阶段不显示“临时”，被正式生成进备选供应商后才按现有机制标记临时。

候选信息栏展示sourcingAt，商品详情顶部展示detailFetchedAt。刷新只读取AC后台数据，不调用1688，也不改变两个时间；重新溯源才更新sourcingAt。

2. 业务页面与结果承接

2.1 参考产品、候选与详情

参考产品保留原系统多选、分页和固定列；右侧固定列顺序为目标采购量、目标采购价、1688溯源、操作。模块右上角不再设置“查看全部货源”，只保留每行“查看货源”和下方1688备选货源中的“全部ASIN”Tab。新增ASIN沿用现有权限，新增成功后系统自动执行该ASIN的增量溯源判断并增加对应Tab，不影响已有ASIN。

目标采购量为0表示未维护：不传MOQ限制，页面展示“起批量不限”，且不影响自动溯源；目标采购量 > 0时才使用“起批量 ≤ 目标采购量”。自动溯源仍按采购价格规则判断。

ASIN Tab与候选表格之间只设置一条轻量信息栏：左侧“溯源条件”略加字重，具体条件使用普通深灰正文；右侧数据获取时间使用更弱的辅助灰。宽度不足时自然换行，不展示接口字段名。

当前任务无参考产品时，1688备选货源统一展示“当前任务暂无参考产品 / 添加参考产品后，系统将自动发起1688溯源”，不得混同于正在溯源、完成0条、未自动溯源或溯源失败。

候选价格优先按商品详情SKU批发价展示区间；缺少SKU明细时才回退搜索价格。已经生成待开发产品的候选禁用复选框并使用深灰禁用态，整行仅轻微置灰且保持原浅色格线，主图轻微弱化；详情和1688原商品链接继续可用，并保留“已转待开发产品”标签。

简版详情按商品概要/采购信息、SKU/变体、商品表现、供应商/商家表现、履约与品质、发票/商品属性分组。各商品级价格按接口原值分别展示，SKU表展示SKU图片、规格、SKU批发价和SKU库存。

候选复选框与详情底部“选择该货源 / 取消选择”实时同步，但选择只形成页面临时集合；真正写入业务数据的是“生成待开发产品（N）”。

2.2 生成前确认、生成动作与防重复

点击生成后先打开“确认开发变体”弹窗，按1688商品分组展示SKU并默认全选。顶部只显示预计生成的SPU/SKU数量和默认全选说明；底部只保留取消与确认生成按钮。分组不显示offerId，收起时展示主图、标题、SKU批发价区间、已选数/总数、全选、清空和状态箭头；点击标题行非操作区域均可展开或收起，全选和清空不触发展开。

一个SKU都未选择时确认按钮不可用；某商品选择0个SKU时不生成该SPU。确认后，一个1688 offer生成一个SPU，每个选中的1688 SKU生成一个待开发SKU，未选择的SKU不生成；SKU采购价取对应1688 SKU批发价。

同时处理备选供应商并保存Amazon ASIN → 1688 offer → 待开发产品正式关系。同一任务 + ASIN + offerId禁止重复生成；重新溯源再次召回相同offerId时继续识别已有关系。

关系字段保存内容
任务与来源taskId、asin、offerId、promotionURL、sourcingBatchId
供应商sellerOpenId、companyName、internalSupplierId（匹配时）
结果pendingProductId、selectedBy、selectedTime、来源=1688备选货源

2.3 备选供应商

沿用现有备选供应商模块与操作，只新增“来源”：手动添加、1688备选货源。匹配成功直接关联内部正式供应商；未匹配按现有机制加入临时供应商。正式供应商按internalSupplierId去重，临时供应商按sellerOpenId去重。

2.4 待开发产品

待开发产品列表和编辑弹窗共用同一份SPU/SKU生成数据。一个offer生成一个SPU，确认弹窗选中的每个变体生成一个SKU；标题、SKU规格、图片、采购价、供应商、参考ASIN和来源保持一致，编辑或删除后立即同步到列表，不维护第二套硬编码数据。

来源字段直接展示“1688备选货源 / 查看原商品 ↗”，链接使用promotionURL，不向用户显示offerId；手动创建的数据仍展示“手动添加”。弹窗继续沿用原业务字段和相同款/相似款选择，不单独展示来源字段。

待维护仅展示在SKU行“预计售价区间”字段上；变体选择已前置，不再把选择哪些SKU作为生成后的待确认事项。

2.5 提交审核校验

任一待开发产品仍有“待维护”、现有必填业务字段未完成或原有校验不通过时，不允许提交，统一提示“当前仍有待开发产品信息未维护，请处理完成后再提交”，并定位待开发产品列表。备选供应商继续执行原有提交校验。

2.6 权限

用户与状态权限
调研中 + 当前任务开发人可新增ASIN、重新/手动溯源、选择货源、生成产品和维护待开发产品
调研中 + 管理员但不是任务开发人可查看、刷新及删除参考产品，无标记权限；其他操作只读
其他查看人或其他任务状态只读；非调研中不允许新增参考产品
拥有任务查看权限的所有角色可刷新、查看货源/详情/供应商/待开发产品/来源关系及打开原商品

验收标准

硬筛选仅包含跨境精选货源、跨境推广链接、商品体验分 > 4.0、采购价和起批量
综合服务分、品质退货率只作详情辅助信息，不参与一期硬筛选
页面溯源条件全部使用业务中文，条件和时间位于同一轻量信息栏
候选价格按SKU批发价展示单价或区间，缺少SKU明细时才回退搜索价格
详情中的四类商品级价格按接口原值独立展示，SKU价格与库存按变体展示
无参考产品空状态与正在溯源、0条、未自动溯源、失败明确区分
调研中新增ASIN自动触发该ASIN的独立溯源判断
新增一个或多个ASIN均为增量处理，不重新溯源已有ASIN

最新确认：编辑与溯源结果生命周期

待开发产品编辑

  • 生成前弹窗标题统一为“确认待开发变体”。
  • 编辑页变体表头仅展示“产品标题”；1688规格作为辅助信息展示在具体产品标题下方。
  • 参考产品按“相同款/相似款”在前、ASIN在后的顺序展示；预计售价区间沿用线上起始价、结束价及USD币种的样式。
  • 候选货源及待开发产品标题最多展示两行，超出显示省略号，悬浮展示完整标题。

删除与重新溯源

  1. 删除SKU只删除该SKU，即使删除到0个SKU也必须保留所属SPU、正式来源关系及货源占用状态，不得自动删除SPU或恢复1688候选。
  2. 只有用户主动删除由1688货源生成的SPU时，才解除该待开发产品与offer的生成关系；若该offer仍在当前候选结果中，恢复其复选框和“选择该货源”能力。
  3. 重新溯源继续使用当前统一准入及采购可行性规则，生成新的溯源批次，并直接覆盖该ASIN原候选数据及数据获取时间，不与旧候选做增量叠加。
  4. 重新溯源只替换候选结果，不删除、覆盖或改写此前已经生成的待开发SPU/SKU、备选供应商及正式来源关系。
  5. 新批次再次召回已生成产品对应的同一offer时，依据任务、ASIN、offer关系继续标记为“已转待开发产品”并禁止重复选择；待开发SPU后续被主动删除时，再恢复当前候选中的对应offer。
删除SKU不删除SPU，也不恢复1688候选
主动删除SPU后，对应当前候选恢复可选
重新溯源覆盖候选数据但不影响已生成待开发产品
同一offer重新召回时仍能识别既有生成关系并防重复
