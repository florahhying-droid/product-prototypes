重点交互场景

普通员工仅能查看自己的权限记录

规则说明
一、选品数据权限规则
权限颗粒度
  • 一条权限 = 1个用户 + 1个公司/全部公司 + 多个三级品类。
  • 同一用户可配置多条，不同记录最终取并集。
  • 具体公司权限仅包含该公司对应品类产品，不包含无公司产品。
  • 【全部公司】权限包含对应品类下全部公司及无公司产品。
管理员
  • 管理员默认拥有全部选品数据权限。
  • 如管理员单独配置了选品数据权限，则配置范围优先。
取消原品线系列权限
  • 删除【品线系列权限】Tab。
  • 原品线系列权限停止生效，历史配置不再参与数据权限判断。
  • 后续统一按照【公司 + 品类】控制到具体产品/ASIN。
二、权限配置与向下授权
谁可以维护
  • 普通用户：仅查看本人权限，本人不可自行编辑。
  • 有下级用户：可查看本人及下级权限；本人只读，下级可新增、编辑、删除。
  • 管理员：可查看、维护所有人员权限。
非管理员授权范围
  • 只能在本人已有的“公司 + 品类”权限范围内给下级授权。
  • 管理员不受公司、品类范围限制。
公司与品类联动
  • 新增/编辑顺序：用户 → 公司 → 品类。
  • 非管理员选择具体公司后，可配置品类 = 本人【全部公司】下的品类 + 本人在该具体公司下的品类。
  • 选择【全部公司】时，只能配置本人【全部公司】权限下的品类。
  • 管理员始终可选择任意公司及完整品类树。
下属已有超范围权限
  • 不隐藏。
  • 下属持有当前上级未持有的公司权限时，该条记录仅可查看。
  • 公司在可授权范围内时，超范围既有品类置灰只读并正常计入已选数量。
  • 保存时超范围既有品类保持不变。
三、权限配置页面交互
重复配置
  • 同一用户 + 同一公司最多一条。
  • 用户、公司选择完成后立即校验。
  • 重复时提示“该用户已配置此公司，请编辑原权限”。
  • 校验未通过不可保存。
  • 【全部公司】与具体公司权限允许同时存在。
品类选择
  • 最终仍按三级品类 L3 保存。
  • L1/L2 支持整体勾选/取消。
  • 部分子级选中时父级显示半选状态。
  • 取消原30个品类上限，显示【已选 X 个】。
列表
  • 同一用户可出现多行，不同公司分别展示。
  • 字段：用户名｜公司｜品类｜创建人｜创建时间｜更新人｜更新时间｜操作。
  • 品类展示数量摘要，如【12个三级品类】，点击进入查看弹窗。
  • 操作保留【查看｜编辑｜删除】。
四、各业务页面的数据权限
产品系列
  • 系列本身不参与权限判断，最终判断系列内具体产品/ASIN。
  • 部分产品有权限：系列展示，仅展示有权限产品。
  • 无任何有权限产品：整个系列不展示。
  • 产品数、销量、销售额等聚合数据，按当前用户实际可见产品重新计算。
  • 数据权限不代表系列/系列产品编辑权限；系列及系列产品管理仅管理员可操作。
精选产品池
  • 复用同一套【公司 + 品类】权限。
  • 筛选结果及卡片宫格只展示当前用户有权限的产品。
  • 具体公司权限不包含其他公司及无公司产品；【全部公司】可包含无公司产品。
  • 当前产品池仅有筛选和卡片宫格，无额外统计处理。
后续 ASIN 选品页
  • 直接复用本次选品数据权限，ASIN 平铺展示，不依赖系列。
  • 查询、筛选、查看均限定在用户有权限的数据范围内。
  • 有权限的 ASIN 可选择创建开发任务。
五、创建开发任务与人员分配
创建任务
  • 拥有对应选品数据权限，即可基于该产品创建开发任务。
  • 选品数据权限不等同于开发任务模块其他管理权限。
开发人员
  • 非管理员：只能选择本人 + 本人下级。
  • 管理员：不限制人员范围。
下一分配人
  • 非管理员：只能选择本人下级，不包含本人。
  • 管理员：不限制人员范围。
  • 与开发任务模块现有人员分配权限保持一致。
历史数据
  • 原品类权限保留原用户及品类范围，公司统一初始化为【全部公司】。
  • 原品线系列权限不迁移，直接停止生效。
  • 新业务首批权限由研发批量初始化，后续通过页面维护。
