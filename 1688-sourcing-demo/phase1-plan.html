目标与一期范围

在开发任务中并行执行1688货源溯源与内部供应商溯源，分别承接外部候选商品和内部供应商结果。两条链路独立执行、独立记录状态，共用任务参考ASIN、备选供应商和现有提交审核流程。

链路输入与处理结果与落点
1688溯源ASIN图片与AI提取关键词 → 搜索召回 → AC去重过滤 → 内部供应商匹配与资质处理 → 综合评分每个ASIN最终最多10个候选商品；人工选择offer与SKU后生成待开发SPU/SKU，并处理备选供应商

共同触发：新建任务成功后处理全部初始参考ASIN；待分配、调研中的任务新增ASIN成功后仅处理新增部分。自动执行不额外要求用户确认，也不扩大新增ASIN、删除ASIN等既有权限。

AI仅为1688搜索提取中文关键词；1688相关性复用接口原始排序，内部相似能力复用现有接口。

供应商信息处理

  • 使用1688公司名称与内部供应商名称精确匹配；地址省市和“渠道-1688”类型仅作辅助校验。匹配成功保存内部供应商ID，并读取实际内部状态和结算方式。
  • 搜索结果不保证返回公司名称；需要参与内部匹配和评分时，用offerId补查商详或复用已获取资料。补查失败记录资料缺失；内部供应商采用名称精确匹配。
  • 从商家身份、诚信通年限等数据提取资质；只展示实际命中的诚信通X年、超级工厂、实力商家，缺失展示“--”，不补造年限或身份。
  • 内部供应商匹配结果用于候选展示与评分；确认生成待开发产品时关联任务备选供应商。内部供应商自动加入属于第二部分独立链路。
评分前获取合格候选所需的供应商资料，优先复用搜索返回字段与缓存；缺少匹配信息时按需补查商详。确定最终候选后补齐SKU等展示详情，调用采用缓存、并发控制和超时处理。

1.4 综合评分与推荐结果

总分100分，由搜索相关性40分和供应商综合评分60分组成。

搜索相关性：40分

  • 使用1688返回的默认相关性排名，图搜权重1.0，关键词权重0.7；排名从1开始。
  • RRF融合公式：R = 1 / (60 + 图搜排名) + 0.7 / (60 + 关键词排名)。仅命中一个通道时，未命中通道贡献为0。
  • 同一ASIN、同一溯源批次，将全部页合并、去重并通过过滤的候选作为统一评分集合，取其中最大的R值为Rmax。搜索相关性分 = 40 × R / Rmax，最高为40分；在最终选取10个商品之前计算，不逐页归一化，不跨ASIN或跨批次共用Rmax。集合为空时直接输出0条；Rmax为0时相关性分记为0。

供应商综合评分：60分

组成情况分值
我司内部供应商（最高35分）匹配有效内部供应商，且有账期35
我司内部供应商匹配有效内部供应商，无账期18
我司内部供应商未匹配内部供应商，或内部状态非有效0
商家资质（最高25分，可叠加）超级工厂15
商家资质实力商家10
商家资质同时具有超级工厂、实力商家25（15＋10）
商家资质仅诚信通会员0；诚信通作为AC准入条件

内部供应商35分、18分档位互斥。内部状态必须读取实际系统状态；草稿、锁定、停用等不能套用“有效供应商”加分。显示了结算方式不等于有账期：“预付款100%”不能算月结账期；阿里月结X天等按内部结算方式字典中的付款类型判断。无法归类时补取核验后评分，记录资料异常。

最终结果

按综合得分从高到低输出，每个ASIN最多10个商品。合格结果不足10条时按实际数量展示，不放宽条件。同一ASIN全部页的候选统一按综合得分排序；总分并列时，依次按搜索相关性分降序、图搜原始排名升序、关键词原始排名升序排序；未命中通道的排名排在已命中之后。

有账期判断使用内部结算方式字典；状态非有效或缺失时内部供应商项记0分；未返回的商家身份不计对应资质分。

1.6 创建待开发产品与信息维护

确认待开发变体

点击“生成待开发产品（N）”打开“确认待开发变体”弹窗，按offer分组显示SKU并默认全选。可取消不开发的变体；某offer选择0个SKU时不生成其SPU；全部SKU未选择时禁用确认。弹窗统计随内容滚动吸顶，确认前展示将生成的SPU与SKU数量。

选中数据业务结果取值与去重
一个offer一个待开发SPU标题、主图、供应商、来源链接取对应offer
一个被选中的1688 SKU该SPU下一个待开发SKU规格、SKU图、采购价、库存取该SKU；参考产品关系默认“相同款”，支持编辑为“相似款”；包装尺寸重量按实际数据维护
匹配的内部供应商关联已有正式供应商任务内按内部供应商ID去重；若已由内部溯源或人工加入则复用，列表首次来源不覆盖
未匹配的1688供应商按现有机制处理临时供应商按供应商公司名称精确去重；来源为1688备选货源

正式关系与防重复

保存任务—参考ASIN—1688 offer—待开发SPU关系，同时保留来源链接、溯源批次、供应商、操作人与时间。同一任务＋ASIN＋offerId禁止重复生成；重新溯源召回同一offer时识别既有关系并保持已转产品标记。生成应统一处理产品、供应商与来源关系，失败时避免只写入部分业务数据。

产品维护

  • 列表和编辑弹窗共用一份SPU/SKU数据；编辑、删除同步，不维护另一套独立展示数据。
  • 来源展示“1688备选货源 · 查看原商品 ↗”，使用搜索promotionURL，兼容商详promotionUrl。手动创建仍显示“手动添加”；历史已有任务供应商来源默认“手动添加”。任务供应商仅记录首次成功加入的来源，解绑后再次加入按本次方式记录。
  • 编辑沿用产品标题、供应商、系统品类、图片、参考产品及相同款/相似款、采购价、预计售价、起订量、包装尺寸重量、友商销售材料等现有字段。
  • 1688规格显示在SKU产品标题下。预生成产品缺少系统品类、预计售价时默认显示红色内联提示；SKU行未维护售价时显示橙色“待维护”标签；编辑表单及提交校验使用红色提示。
  • 长标题最多两行省略，悬浮看全文；SKU和SPU删除均需二次确认。

2.3 自动加入、去重与来源规则

规则处理方式
自动加入完整匹配结果先保存在后台；符合当前开发人加入规则时自动纳入任务备选供应商，不要求开发人再次选择
任务内去重按内部供应商ID唯一识别；多个ASIN、多个相似SKU或两种相似方式命中同一家供应商时，任务内仍只保留一条
跨链路复用与手动绑定、1688生成产品共用去重规则；已在任务中的供应商不重复添加
首次来源仅在首次实际成功加入当前任务备选供应商时记录来源；仅后台匹配、尚未加入时不提前记录列表来源；重复命中或展示变化不覆盖
来源枚举手动添加 / 内部供应商溯源 / 1688备选货源；内部自动匹配加入时记录“内部供应商溯源”
分配 / 更换开发人及刷新基于完整匹配结果重新判断加入与展示；未加入且现已符合条件的供应商可自动加入。已有关系及首次来源保留；隐藏不等于解绑或删除，不清空已有产品绑定
重新溯源只补充新命中且符合加入条件的供应商；不自动删除本次未命中的已有供应商，不覆盖已有产品、人工维护或首次来源
解绑后再次加入按本次实际加入方式重新记录来源；重新命中且符合加入条件时可再次加入，不设置永久排除名单
删除参考ASIN / 待开发产品内部供应商当前溯源内容、匹配关联及历史批次不自动删除；已加入备选供应商不自动删除，已有来源追溯信息保留
待授权供应商获得权限保留原备选供应商关系及首次来源，按最新权限恢复完整展示和使用，不重复添加；对于原先仅后台匹配、未加入且现已符合条件的供应商，刷新时可首次加入
来源示例：先由内部供应商溯源加入，之后通过1688商品生成产品，来源仍为“内部供应商溯源”；先手动加入，之后重复命中，仍为“手动添加”。解绑后再次由1688生成产品加入，来源记录为本次的“1688备选货源”。

保留供应商与相似SKU、参考ASIN、匹配来源（标题 / 图片）及批次时间的关联。后台全部命中记录与前端首次加入来源分别保存；同一供应商的多来源命中不在列表重复堆叠。

创建时未分配开发人，溯源正常完成并保存结果，列表不展示内部溯源供应商。首次分配、更换开发人，以及模块或页面刷新时，基于已保存的全部匹配结果，按当前开发人的部门和最新权限重新判断加入、可见性、脱敏及可用状态。已保存但尚未加入且现已符合条件的供应商自动补入；既有供应商关系和来源保留，不因隐藏而删除，也不清空已有产品绑定。

负责人在现有供应商权限流程中完成授权后，刷新备选供应商模块或任务页面，按当前任务开发人的最新权限恢复完整名称，同时移除“待授权”标签和负责人信息。刷新不重新执行溯源，不产生新的溯源执行批次。已有关系不重复新增、首次来源不变；原先未加入且现已符合条件的匹配供应商可首次加入并记录来源。其他用户查看、刷新同一任务时，展示结果仍以任务开发人的权限为准。

  • 已绑定的供应商不因后续权限变化自动清空或替换；新增或变更绑定时，后台按最新权限校验。

2.8 场景化验收

场景预期结果
创建任务包含多个ASIN自动触发两条独立链路；内部供应商按钮先显示溯源中，完整保存全部匹配结果；已分配开发人时按部门及权限规则加入并展示
创建任务时未分配开发人正常完成溯源并完整保存匹配结果；列表无内部溯源供应商，渠道供应商也不例外；不当作失败
首次分配开发人不重新溯源；从已保存结果按开发人部门与权限判断加入及展示，首次实际加入时记录来源
更换开发人不重新溯源；按新开发人更新可见性、脱敏及可用性，保留原匹配、已有供应商关系、首次来源和已有产品绑定
刷新时原先隐藏供应商已获得权限复用已保存结果恢复展示，原先未加入的可自动补入；已有关系不重复添加，不产生新的溯源执行批次
新增一个或多个ASIN只匹配新增ASIN；已有供应商去重，全部内部批次完成后恢复按钮
标题与图片命中相同SKU合并去重，保留双来源与供应商关联，可按来源分析结果及增量贡献
同一SKU关联多个供应商，含非默认供应商获取全部关联供应商，按当前任务开发人权限分流，不只获取默认供应商
多个SKU / 多个ASIN关联同一家供应商同一任务只新增一条；后台保留各匹配关联
星渠任务命中权限外精品 / 泛精品供应商自动加入；名称脱敏、橙色待授权标签、名称下灰色负责人；不在产品供应商下拉中提供选择
其他部门命中权限外精品 / 泛精品供应商列表不展示，后台完整匹配结果保留；后续开发人或权限变化时可重新判断
已分配开发人的任务：渠道供应商 / 各部门有权限供应商正常加入、完整展示并允许使用；不展示待授权标签及其负责人辅助信息
待授权供应商获得权限刷新模块、页面或供应商可选列表后恢复完整名称、移除待授权及负责人信息、允许选择；保留原供应商关系及来源
不同用户查看或刷新同一任务供应商权限、脱敏及可用状态始终以当前任务开发人为准
已有绑定供应商后续权限变化不自动清空或替换已有绑定；新增或变更绑定时后台按最新权限校验
已内部溯源加入后从1688生成产品复用供应商，来源仍为内部供应商溯源
已手动绑定后内部溯源命中不重复新增，不覆盖手动添加来源；过程记录识别为匹配前已有
重新溯源未命中某家已有供应商只补充新供应商，已有供应商和产品不受影响，历史批次不覆盖
解绑后重新命中符合加入条件时可再次加入，按本次加入方式重新记录来源
删除参考ASIN / 待开发SPU或SKU内部溯源内容和匹配历史不自动删除；已加入备选供应商保留；1688候选按第一部分规则单独处理
命中供应商较多不按1688候选商品数量截断，符合加入条件的供应商全部加入并沿用现有分页
结算方式为预付款 / 阿里月结 / 缺失按原值展示，缺失为“--”；供应商状态按实际值展示
相似SKU为空 / 无关联供应商 / 权限处理后无展示结果 / 全部重复正常完成，自动更新列表和数量，提示“内部供应商溯源完成，新增 0 家供应商”
接口失败 / 执行中重复点击失败保留旧数据、恢复按钮并提示“内部供应商溯源失败，请重新尝试”；执行中按钮禁用
管理员、查看人或审核中用户沿用任务可见范围，可查看、刷新；不开放重新溯源、绑定解绑等写权限
过程数据与后续应用可追溯原始召回、SKU合并、供应商关联与去重、权限识别、匹配前已有 / 本次新增、后台匹配与列表展示数量、分配或更换开发人、权限刷新、后续授权及产品应用；来源和批次记录完整

A.2 内部供应商接口与数据

复用现有ASIN英文标题相似SKU、重复开品图片相似、SKU关联供应商查询及供应商权限能力。接口名称、入参出参和调用身份引用现有接口文档，不在本方案新增虚构契约。完整保存全部匹配结果，不受开发人分配或变更影响；基于已保存结果按当前任务开发人识别部门及最新权限，返回当前应展示的供应商编号、按权限展示的名称、状态、类型和结算方式。未分配开发人时无内部溯源展示结果；分配、更换开发人及刷新不重新执行溯源，可按加入规则补入原先未加入的供应商；星渠待授权供应商同时返回待授权标识及负责人，授权并刷新后恢复完整名称、移除标识及负责人。后台按2.6保留标题 / 图片匹配依据、各阶段明细、权限识别及产品应用关联。接口契约复用现有能力。
